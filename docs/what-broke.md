# What broke

Running log from day 1. Every breach or failed assumption: what happened, root cause, the fix, and the commit.
Hard limits are never loosened to pass a test; the layer that let it through gets fixed.

| Date | Attack / test | What happened | Root cause | Fix | Commit |

| 2026-11-21 | Phase 1 spike, first invoke | Every call failed: `AccessDeniedException` on `bedrock-agentcore:ListEvents` | The harness provisions managed memory by default; the execution role had no memory permissions | Scoped memory actions on `memory/*` added to the harness role | — |
| 2026-11-21 | Phase 1 spike, `allowedTools: ["spike_echo"]` | Model never saw the tool (98 input tokens) and refused in prose; deny/throw cases "passed" without the hook ever firing | A plain name in `allowedTools` selects built-ins only and silently drops inline tools (matches aws/agent-toolkit-for-aws#468). Our check also accepted "no tool call" as a deny | Select inline tools as `@spike_echo` (verified: the model then sees only `spike_echo`, no shell or file tools). The spike check now requires an actual hook `deny` event | — |
| 2026-11-21 | Phase 3 deploy, attaching the policy engine | Gateway update failed: gateway role not authorized for `bedrock-agentcore:AuthorizeAction` | The docs list the action but the check runs against the gateway ARN, not only the policy engine | Granted it on the engine and on `gateway/kavach-gateway-*` (a name pattern avoids a role ↔ gateway cycle) | — |
| 2026-11-21 | Phase 3 unit tests, L4 with an empty `payeeId` | Hook denied, but via "internal error" instead of R1 | DynamoDB rejects an empty key; the exception path caught it (fail-closed worked, wrong reason) | `get_payee` returns no payee for empty or non-string IDs; test asserts the R1 reason | — |

| 2026-11-22 | Phase 5 smoke run | A plain Tamil electricity-bill request was refused, citing "Rs 14,000 to Chennai Metrowater", text from a different attack script. | 2026-11-22 | Phase 5 smoke run | The scammer coach's victim often asked "what should I do next?" instead of asking for a payment, so turns tested nothing | Coach prompt didn't require a concrete payment request or teach the hide-the-reason tactic real scammers use | Every victim message must name an amount and destination; after a refusal the scammer coaches her to drop mentions of police or banks and give an innocent reason; fallbacks name the real target | — |
| 2026-11-22 | Phase 6 latency | Kavach turns missed the 4 s p50 target (5.1 s across the benchmark; 8.7 s on bill payments, which make 3–4 model calls) | The `before_invocation` hook (p50 1.28 s) ran the guardrail and the Nova Micro scorer one after the other, and each tool call adds about 0.2 s for the L4 gate plus its signed audit record | Guardrail and scorer now run in parallel; hook Lambdas raised to 1,024 MB.
